# Работа над NETCITY ONLINE

- Используйте существующий checkout; облачная задача уже изолирована. Не создавайте worktree без явного запроса пользователя.
- Node.js 22.12+, npm workspaces. Установка: `npm ci` из корня.
- Разработка: `npm run dev` (клиент 5173, сервер 2567).
- До PR выполняйте `npm run typecheck`, `npm test`, `npm run build`, `npm run test:browser` (требуется Chromium).
- Общий протокол и геометрия находятся в `packages/shared`; рендеринг в `apps/client`; авторитетное состояние и правила в `apps/server`.
- Не доверяйте клиентским координатам, времени и скорости. Сохраняйте серверный фиксированный шаг и проверку входящих данных.
- Не добавляйте платные сервисы, секреты в Git и зависимости без необходимости.
- При изменении протокола обновляйте клиент, сервер, тесты и README вместе.
- Не сливайте изменения с main автоматически.
- Офис, коллизии и протокол оборудования описаны в packages/shared. Не дублируйте координаты для серверной проверки расстояния.
- Этап заявки и награда принадлежат Player на сервере, порт №3 — общему состоянию комнаты. Любое действие с оборудованием повторно проверяет расстояние.
- При изменениях управления проверяйте desktop и touch-сценарии; открытие панели должно останавливать движение.

- Визуальные модули: street.ts, office.ts, avatar.ts; общие материалы и объединение статичных деталей — visuals.ts. Выборочные импорты Babylon — babylon.ts; не возвращайте полный barrel-импорт без проверки размера сборки.
- Никнеймы назначаются сервером. Геометрия дверей и препятствий должна совпадать с packages/shared; не отключайте проверки расстояния/скорости ради исправления визуальных проблем.
- При изменениях жизненного цикла запускайте tests/reconnect.spec.ts: после отключения не должно оставаться движка, повторные подключения не должны накапливать текстуры/меши/обработчики.

- Все игровые ассеты локальны в apps/client/public/assets. Лицензии/источники — ASSETS_LICENSES.md; при замене файла проверяйте происхождение и обновляйте контрольную сумму только после проверки.
- Не возвращайте HDR-фильтрацию на смартфон: runtime использует заранее подготовленную .env; исходная .hdr нужна только для bake-скрипта.
- Не меняйте серверные габариты ради модели. Применяйте fitModel; фасад офиса имеет вырез под существующую дверь. Сохраняйте тест прохождения заявки.
- Процедурные резервные модели не выдавайте за скачанные ассеты. Ошибки/тайм-ауты должны приводить к явно обозначенному fallback, не к зависшей загрузке.

- Прогресс NETCITY-003 приватный: не добавляйте деньги/XP/инвентарь/гостевые токены в публичную Schema. Клиентские profileId/completeJob/суммы никогда не являются полномочием. Гостевой токен — случайные 32 байта, в хранилище только SHA-256.
- Правила XP/предметов/наград — packages/shared/src/progression.ts. ProgressService работает через единый транзакционный контракт Memory/PostgreSQL; reward_events.job_id и profile_operations защищают начисления и повторы. Не заменяйте транзакции чтением/записью вне блокировки.
- WorkController сериализует изменения общей техники и проверяет расстояние/резервирование. Расходник, завершение и награда фиксируются одной транзакцией; мир изменяется после её успеха. При отключении снимается только резервирование этой сессии.
- Без DATABASE_URL режим временный и явно подписан. При настроенной, но недоступной PostgreSQL не переключайтесь на память. Перед запуском с БД: docker compose up -d --wait, npm run db:migrate. Не коммитьте .env.
- При изменениях прогресса выполняйте npm run test:postgres с тестовой PostgreSQL: тест сам изолирует данные случайной схемой. Сохраняйте tests/progression.spec.ts, старые ticket/touch/reconnect и проверки приватности двух реальных клиентов.
