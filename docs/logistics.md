# NETCITY 5.0 transport and deliveries

Depends on diagnostics PR #33 and world PR #32. The server simulates acceleration, braking, steering, oriented collision, road boundaries, traffic stop lines and safe parking exits at a fixed step. Client messages supply intent, never position, speed, ownership or amounts. One free van is assigned per profile; the existing warehouse-van upgrade increases capacity. The current deployment uses one authoritative process; process-local fleet leases also prevent the same profile spawning/driving a second copy in another room. Multi-process deployment requires durable fleet leases before enabling it.

Nine deliveries combine a supplier order, a physical held/dropped carton, owned boot loading, actual travel, destination unloading, indoor installation, a product-specific test and client signoff. A prepaid starter needs no initial funds. Capacity is checked before charging for heavy stock. Case parts transfer transactionally between carried state and boot, with exactly one authoritative representation. Shared dropped parcels have visible collision; only their owner's delivery can collect them.

Optional `business.logistics` JSONB stores the van ID, zero-speed parking checkpoint, case cargo and current delivery. No schema migration, account copy or legacy case reset. Periodic parking checkpoints bound crash-position recovery; cargo custody commits with the operation. Disconnect stops the van immediately, drops a held package and checkpoints the pose. All budget/part movements and delivery rewards use existing profile locks, operation fingerprints and reward uniqueness.

Validation: typecheck/build, 67 server tests, 19 real PostgreSQL tests, two-client ownership/forgery/disconnect scenarios and browser supplier-to-payment/reload plus touch. Actual authored model bounds inspected at approximately 1.97 × 2.16 × 4.20 m. Legacy cases/projects remain intact. Production is unchanged; integrated company/co-op acceptance and final staging remain release gates.
