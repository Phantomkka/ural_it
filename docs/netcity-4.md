# NETCITY 4.0 · Field crews

The release adds persistent projects for one to five distinct player profiles. The tablet's **Бригада · 4.0** app offers 27 repeatable projects across nine district interiors: turnkey surveillance, network deployment and equipment renewal. The previous 44 individual jobs, accounts, settings and company upgrades remain available.

Create a crew, give its 12-character invitation code to friends, choose roles and launch the trip. Launch fixes the roster and payment shares; roles are coordination labels and any member can finish a disconnected colleague's work. A sixth profile cannot join. Each profile has one active crew project; after customer signoff and collecting its own share it can create another project.

Each project includes a customer survey, requisition, warehouse collection and physical delivery, a five-point cable route with termination and testing, two equipment installation workflows and final acceptance. Surveillance installs two cameras with brackets, power checks, framing and recording tests. Network and renewal jobs preserve configuration, isolate power, replace hardware, restore configuration and run a timed load test. The supplier stocks camera kits, PoE switches, cable kits, routers, UPS units, backup disks and printers. Packing takes server time. Parcels can be put down, handed to a colleague and recovered after disconnects. One account's second browser cannot teleport its carried parcel.

Client procurement funds are isolated from player money: each required kit is ordered at most once, budget is deducted atomically and unused funds cannot be withdrawn. The contract's total payout is divided by the fixed crew size, not multiplied by it. Each participant claims one durable ledger reward, including after reconnecting or switching devices. Completed projects contribute to company work counts. Projects can be repeated without a daily cap.

Shared progress, parcels and pending tests persist in `crew_projects`; migration 009 adds that table and a default empty `profiles.projects` column. Original inventory, credits, XP, jobs, accounts, sessions, settings and active service/cable tasks are untouched. Profile binding retains the same profile ID. Project mutation locks precede profile locks, including across separate server processes. Public scene objects contain geometry/state and session references only; profile IDs, private balances and invitation codes are not broadcast.

Ground-floor equipment and camera/cable installation visuals are authored modular geometry using the existing renderer and licenses. The release does not add drivable transport, arbitrary rigid-body simulation, free-form electrical work or real surveillance streams. Upper floors remain scenery. Roles do not require five simultaneous players: a solo engineer can also finish a contract.

Before deployment, build immutable SHA images, validate an isolated PostgreSQL staging project, then pause only the game server and create a new private database/config backup. Restore it in an isolated database and compare every row. After migration compare every original field again before starting the release with the same volumes and secret. Keep the verified account-compatible maintenance images; an ordinary application rollback must preserve the current database and the new project table. Database restore is a separate recovery action because it would discard newer play.
