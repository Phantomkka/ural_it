# NETCITY ONLINE

Браузерный многопользовательский прототип про системных администраторов: город, доступный офис, повторяемые IT-заявки, NET/XP и инвентарь. TypeScript, Babylon.js, React + Vite, Node.js + Colyseus, npm workspaces. До 32 игроков в комнате. Кредиты NET строго виртуальные. Полноценных аккаунтов, реальных платежей и платных сервисов нет. PostgreSQL сохраняет гостевые профили; без него работает явно обозначенный временный режим.

## Запуск

Node.js 22.12+ и npm 10+:

```sh
npm ci
npm run dev
```

Откройте `http://localhost:5173` в двух вкладках или на двух устройствах. Для телефона в локальной сети используйте адрес компьютера с Vite, порт 5173. Сервер слушает 2567; Vite проксирует HTTP matchmaking и WebSocket через `/game`. Не выставляйте Vite dev server в публичный интернет.

На компьютере: нажмите на сцену, WASD — движение, мышь — обзор, E — осмотр, Esc — освободить курсор/закрыть панель. На телефоне: джойстик слева, свайпы справа, кнопка «Осмотреть». Поддерживаются два пальца одновременно; открытие панели, потеря фокуса и уход вкладки в фон останавливают движение.

## Заявка №001

При подключении выдаётся «В офисе пропала сеть». Найдите офис №001 справа от центрального пешеходного перехода. Пройдите через открытую дверь, коридор и вторую дверь в серверную. Подойдите к коммутатору не дальше 2,5 м, наведите прицел и нажмите E/«Осмотреть». Подключите отключённый патч-корд в порт №3. Другой порт не завершает заявку.

Первый осмотр автоматически принимает вводный экземпляр заявки. Сервер проверяет позицию, предварительный осмотр, правильность порта, резервирование оборудования и однократную награду: 100 NET и 60 XP. Ремонт виден всем игрокам: порт становится зелёным, кабель подключается. Пока работу выполняет другой инженер, забрать её награду нельзя. Новые экземпляры создаются сервером по правилам доски, а не повторной отправкой команды.

Переподключение создаёт новый сетевой сеанс персонажа, но гостевой токен восстанавливает его профиль и задания. Оборудование хранится в памяти комнаты; после удаления пустой комнаты или перезапуска сервера мир сбрасывается. С PostgreSQL профиль, деньги, XP, инвентарь и история наград сохраняются; во временном режиме они живут только до перезапуска процесса сервера.

## Графика и ассеты

[ASSETS_LICENSES.md](ASSETS_LICENSES.md) содержит авторов, источники, лицензии и ограничения. Все 20 моделей GLB, встроенные текстуры и освещение находятся в `apps/client/public/assets`; игра не обращается к сторонним сайтам. Манифест содержит SHA-256 моделей. Архитектура, деревья, фонари, мебель, урны, машины и светофоры взяты из бесплатных наборов Kenney/KayKit; персонажи с одеждой и клипами Idle/Walk — из CC0-набора Quaternius. HDRI — Poly Haven через публичное зеркало; для игры заранее подготовлен cubemap `.env` размером около 278 КБ, поэтому устройство не выполняет тяжёлую HDR-фильтрацию при запуске.

Новые модели зданий нормализованы под существующие серверные габариты; координаты, скорость и коллизии игрового мира сохранены. Повторяющиеся статичные модели используют Babylon instances, персонажи разделяют исходную геометрию/материалы, но имеют отдельные скелеты и анимации. Внешность детерминирована идентификатором сессии и одинакова у всех наблюдателей; никнейм назначает сервер. Idle и Walk плавно смешиваются по подтверждённому перемещению.

Загрузка асинхронная, с индикатором и ограничением параллелизма. При ошибке или тайм-ауте файла остаётся явно обозначенная резервная графика; механики заявки и мультиплеер продолжают работать. Переподключение повторяет загрузку. Незавершённые запросы отменяются при выходе, созданные контейнеры/скелеты/анимации/текстуры освобождаются.

Городские наборы **стилизованные, не фотореалистичные сканы**. Сетевые ограничения не позволили скачать фотографические кирпичные/бетонные/асфальтовые PBR-карты и готовые серверные стойки с проверенной лицензией. Эти поверхности, стойка, коммутатор, патч-панель, кабели, компьютеры, стеклянные остановки и заборы созданы кодом проекта и не выдаются за скачанные профессиональные ассеты. Машины и новая мебель — визуальные декорации; отдельная симуляция/новая система коллизий для них не добавлена.

## Качество и производительность

В HUD доступны настройки, сохраняемые локально:

| Режим | Разрешение относительно CSS | Тени | Дальность тумана |
| --- | --- | --- | --- |
| Низкое | 67% | выключены | 28–65 м |
| Среднее | 100% | PCF 1024, обновление через кадр | 40–100 м |
| Высокое | 125% | PCF 2048 | 40–100 м |

На телефоне по умолчанию низкое, на компьютере среднее. Во время загрузки тени отключены, выбранный режим активируется после готовности моделей. Размер не умножается на devicePixelRatio. При запуске на низком качестве и на сенсорных устройствах MSAA отключено; для смены этого свойства WebGL-контекста после выбора режима нужно переподключиться. Тяжёлые постэффекты не используются. Для металла, стекла, асфальта и бетона применяются PBR-материалы; отражения используют локальное освещение Poly Haven. Модели с лишними анимациями сокращены до Idle/Walk. Поиск цели выполняется 10 раз в секунду.

60 FPS на среднем игровом ПК и 30 FPS на среднем смартфоне — **цели, не подтверждённые показатели реальных устройств**. Для воспроизводимого локального измерения используйте `node scripts/measure-graphics.mjs`: два игрока, до 30 кадров/3 секунд прогрева и до 120 кадров/10 секунд измерения для каждого режима; число реальных отсчётов записывается в результат. Результат сохраняется в `benchmarks/graphics-swiftshader.json`. Chromium с SwiftShader и эмуляция мобильного экрана не заменяют испытания на физическом ПК/телефоне.

## Проверки

```sh
npm run typecheck
npm test
npm run build
npm run test:browser
```

Серверные тесты проверяют ввод/скорость, стены/двери, расстояние и порт взаимодействия, защиту награды, настоящие два соединения Colyseus. Проверки ассетов сверяют контрольные суммы, GLB-заголовки, встроенные ресурсы, скелеты и анимации. Браузерные сценарии проверяют реальные модели/инстансинг, настройки качества, резервную графику, мультиплеер, заявку, мобильный UI, мультитач и переподключения. Проверяются освобождение движка, стабильность количества ресурсов после загрузки и удаление именных текстур.

Требуется Chromium (`/usr/bin/chromium`, другой путь — `CHROMIUM_PATH`). Playwright сам запускает dev-сервер. Функциональные сценарии под программным SwiftShader используют низкое качество; переключение среднего/высокого проверяется отдельно. Тестам холодной загрузки и нескольких повторных подключений предоставлен больший тайм-аут; это не изменение игровых правил.

## Структура

- `apps/client/src`: HUD/управление, world.ts — жизненный цикл, assets.ts — локальные контейнеры, assetDistrict.ts — размещение моделей, avatar.ts — скины/анимации, quality.ts — настройки/освещение. street.ts и fallbackAvatar.ts используются для резервной графики.
- `apps/server/src`: авторитетное состояние Colyseus, фиксированные 30 Гц, проверка ввода и оборудования.
- `packages/shared`: общий протокол и неизменённая геометрия коллизий.
- `scripts/prepare-assets.py /tmp/netcity-asset-sources`: загрузка закреплённых ревизий источников, проверка исходных хешей персонажей, воспроизводимая конвертация. `scripts/prepare-office-facade.py` адаптирует исходную модель фасада под дверь офиса, сохраняя UV/материалы.
- `node scripts/bake-environment.mjs`: однократная предварительная фильтрация исходной HDRI в runtime `.env` через Chromium/Babylon. Требуется свободный порт 5173.
- `scripts/prepare-assets.py`: упаковка выбранных источников в GLB, встраивание текстур, удаление лишних анимационных данных. Источники и их хеши описаны в манифесте/лицензиях.

Сборка клиента — `apps/client/dist`. В production раздавайте её HTTP(S)-сервером с проксированием `/game` и WebSocket на игровой сервер. Альтернатива при сборке: `VITE_SERVER_URL=wss://your-game-host`. Сервер запускается `npm run start -w @netcity/server`; `PORT` меняет 2567, тогда также требуется обновить proxy Vite. `vite preview` не заменяет production proxy.

## NETCITY-003: работа, развитие и снабжение

Основа этой ветки — **PR #6 / feat/netcity-graphics-overhaul**, коммит `a7d84c80bca0900eb7b97d97c7a8454c4617301f`. Зависимости: PR #2 → #4 → #5 → #6; ветка не требует слияния в старый main для локальной проверки. Изменения реализуют [Issue #7](https://github.com/Phantomkka/ural_it/issues/7).

В правом HUD показаны виртуальные NET, уровень, XP и режим хранения. Кнопка **«Работа и снабжение»** открывает профиль, доску заявок, инвентарь и покупки. У каждого заказа есть серверный UUID, цель, награда, статус «Доступна / Взята / Выполнена» и технический этап. Одновременно активна одна работа; её можно отложить, с задержкой повторного принятия 5 секунд. Выполненные экземпляры не активируются заново. Через 30 секунд сервер создаёт следующий экземпляр с новым ID; доска обновляется каждые 5 секунд. В профиле остаются последние 20 завершённых экземпляров, UI показывает последние четыре, а журнал наград в PostgreSQL не обрезается.

| Работа | Действия в серверной | Награда | Расходник |
| --- | --- | --- | --- |
| Сетевой порт №3 | Навести прицел, E/«Осмотреть», подключить порт №3 | 100 NET, 60 XP | Первая вводная заявка использует найденный кабель; последующие требуют один патч-корд |
| Охлаждение стойки | Принять заказ на доске, подойти к стойке, E, «Осмотреть охлаждение», «Очистить охлаждение» | 80 NET, 50 XP | Один баллон для очистки; нужен набор инструментов |

Новый профиль начинает с 0 NET, 0 XP и одним набором инструментов. В снабжении: патч-корд — 30 NET, баллон — 20 NET, набор инструментов — 50 NET (не более одного). Расходник списывается **только при успешном ремонте**, в одной транзакции с наградой. Неудачная проверка расстояния, отсутствие осмотра, нехватка предмета и повтор команды не списывают расходник. Инструменты не расходуются; лишняя покупка возвращает понятный отказ.

Таблица уровней: 1 — от 0 XP; 2 — от 60; 3 — от 180; 4 — от 360 (учебный предел уровня). После предела XP продолжает учитываться. Правила, цены и награды находятся в `packages/shared/src/progression.ts`.

Техника общая, задания персональные. Принятие работы резервирует соответствующее оборудование на 60 секунд и создаёт учебную неисправность в мире. Осмотр продлевает резервирование. Другой инженер видит изменения, но не может выполнить чужой экземпляр. При отключении резерв снимается; активная заявка остаётся в профиле, и после возвращения нужно заново осмотреть оборудование. Истёкшее резервирование освобождается сервером при обработке действий/обновлений. Это учебные сценарии неисправностей, а не случайная сложная сетевая симуляция.

### Ручное прохождение

1. Запустить игру, войти в офис справа от центра улицы, пройти в серверную. Осмотреть коммутатор и подключить порт №3: баланс 100 NET, 60 XP, уровень 2.
2. Открыть «Работа и снабжение», купить баллон за 20 NET и взять обслуживание охлаждения. Закрыть профиль, снова навести прицел на стойку/коммутатор, нажать E, осмотреть и очистить охлаждение. Баллон исчезнет, баланс станет 160 NET, XP — 110.
3. После задержки взять новый экземпляр ремонта порта, купить патч-корд за 30 NET, осмотреть и подключить порт №3. Получится 230 NET, 170 XP; патч-корд будет израсходован. Спам портом не изменит баланс.
4. Перезагрузить вкладку/переподключиться. С тем же гостевым токеном профиль восстановится. Для двух независимых игроков открыть две новые вкладки или разные браузеры.

### PostgreSQL и миграции

Быстрая проверка по-прежнему не требует Docker: `npm ci && npm run dev`. Если `DATABASE_URL` отсутствует, и в консоли, и в HUD явно отображается **«Временные данные»**. Это не постоянное хранилище.

Для постоянного локального профиля нужны Docker с Compose v2 и Node.js 22.12+. Из корня репозитория:

```sh
npm ci
npm run db:configure
# Генерирует случайный локальный пароль и .env с правами 0600.
# Уже существующий .env НЕ перезаписывается.
docker compose up -d --wait
npm run db:migrate
npm run dev
```

Одной командой подготовить новую БД: `npm run db:configure && docker compose up -d --wait && npm run db:migrate`. Другой свободный порт: `POSTGRES_PORT=55432 npm run db:configure`. При существующем `.env` задайте свои `POSTGRES_DB`, `POSTGRES_USER`, `POSTGRES_PASSWORD`, `POSTGRES_PORT` и `DATABASE_URL` по `.env.example`. Для своей БД достаточно корректного `DATABASE_URL`. Файл `.env` и настоящие пароли не добавляются в Git. Порт PostgreSQL опубликован **только на 127.0.0.1**, данные находятся в Docker volume. Не удаляйте volume, если нужен профиль; `docker compose down` сохраняет его.

Если `DATABASE_URL` задан, ошибка подключения или отсутствие миграции **останавливают запуск сервера**, без скрытого переключения в память. `/game/health` возвращает режим хранения; при потере БД — HTTP 503. Незавершённая транзакция не подтверждается клиенту. После восстановления связи используйте «Повторить ту же операцию»: сохраняется тот же idempotency key.

### Гостевой доступ и приватность

Сервер создаёт случайный 256-битный bearer-токен; в PostgreSQL сохраняется только SHA-256 токена. Сам токен получает только клиент создания профиля, без вывода в консоль или UI. Клиент хранит его в `sessionStorage`: он переживает reload и перезапуск сервера, пока сохраняется вкладка. Разные новые вкладки получают независимых гостей. Закрытие вкладки/очистка хранилища может лишить доступа к профилю; полноценное восстановление аккаунта не реализовано. Это **учебный гостевой механизм, не production-аккаунты**. Знание токена даёт доступ к профилю — не публикуйте его.

`playerId` из команды не является подтверждением владения: сервер определяет профиль только по проверенному токену при входе. Приватный снимок денег, XP, инвентаря и доски отправляется лишь владельцу; публичная Schema комнаты содержит персонажей и оборудование. Даже при нескольких соединениях с одним токеном списания/награды сериализуются по строке профиля.

PostgreSQL-транзакция блокирует профиль `FOR UPDATE`, сохраняет изменение денег/XP/предметов/заказа и уникальное событие награды. `reward_events.job_id` уникален; `profile_operations` имеет PK `(profile_id, idempotency_key)` и проверку отпечатка содержимого запроса. Повтор покупки тем же ключом не списывает деньги снова; смена содержимого при старом ключе отклоняется. Клиент сохраняет неподтверждённую операцию до ответа, в том числе при reload/переподключении. Финансовые поля и максимум одной активной работы проверяются также ограничениями БД. Действия ограничены сервером: запас 16 запросов, восстановление 4/с, очередь комнаты до 64; создание гостей через HTTP ограничено отдельно.

PG-тесты создают отдельную случайную схему, применяют миграцию дважды для проверки повторного запуска и удаляют **только свою** схему. Пользовательские таблицы/профили не очищаются. Проверяются конкурентная награда и покупка, отрицательный остаток, подмена/повтор ключа, расходник, один активный заказ, права на профиль, cooldown/новый ID, откат транзакции и восстановление после настоящего перезапуска игрового сервера и пула PostgreSQL. Браузерный маршрут выполняет весь цикл реальными кнопками и управлением; отдельный touch-сценарий проверяет узкий экран и отсутствие пересечений HUD с управлением.

Ограничения: две учебные работы, четыре уровня, без торговли между игроками, износа инструмента, полноценных аккаунтов и постоянного мира. Оборудование и координаты не сохраняются в БД. Таблица FPS выше получена до NETCITY-003; новые показатели на физических ПК/смартфонах не измерялись. Визуальные ассеты и качество сохранены, клиент не получает библиотеку PostgreSQL.
