# NETCITY ONLINE

Первый рабочий прототип браузерной 3D MMO: одна общая улица, до 32 игроков в комнате, вид от первого лица. Бесплатные open-source библиотеки; внешние сервисы и аккаунты для игры не нужны.

## Запуск

Требуется Node.js 22.12+ (проверено с 24) и npm 10+.

```sh
npm ci
npm run dev
```

Откройте `http://localhost:5173` в двух вкладках или разных браузерах. Нажмите на улицу для захвата мыши. WASD — движение, мышь — обзор, Esc — освободить курсор. На сервере появятся два игрока; каждый видит второго как низкополигонального инженера с анимацией ходьбы и серверным никнеймом. Закрытие вкладки удаляет игрока. Кнопка «Переподключиться» создаёт новую сессию после разрыва связи.

Для игры с другого компьютера в локальной сети откройте адрес компьютера с Vite на порту 5173. Захват мыши зависит от политики браузера; для удалённого размещения используйте HTTPS. Vite проксирует `/game` (HTTP matchmaking и WebSocket) на сервер `127.0.0.1:2567`. Не выставляйте Vite dev server в публичный интернет.

## Команды

```sh
npm run typecheck
npm test
npm run build
npm run test:browser
npm run start -w @netcity/server
```

Сборка клиента находится в `apps/client/dist`. Для production раздавайте её через HTTP(S) сервер и проксируйте `/game` с поддержкой WebSocket на игровой сервер. Альтернатива — установить `VITE_SERVER_URL=wss://your-game-host` при сборке клиента. Серверный порт задаётся через `PORT` (по умолчанию 2567); при изменении порта также измените целевой адрес proxy в `apps/client/vite.config.ts`. `vite preview` не заменяет production proxy.

## Модули

- `apps/client`: React UI, Vite, Babylon.js; сцена, управление и визуализация реплик состояния.
- `apps/server`: Node.js, Colyseus; создание комнат, жизненный цикл игроков, авторитетная симуляция.
- `packages/shared`: протокол ввода, размеры зданий, ограничение скорости и столкновения.

Сервер обновляет мир 30 раз в секунду. Клиент отправляет только намерение движения, не координаты и не время. Нормализация диагонали ограничивает скорость до 5 единиц/с; частота сообщений не ускоряет игрока. Некорректные числа и ввод вне диапазона отбрасываются. Ввод истекает через 250 мс без сообщений, поэтому потерявший связь клиент не продолжает двигаться. Здания и границы мира проверяются на сервере. Клиент показывает подтверждённое положение своего игрока, остальные позиции визуально сглаживает.

## Проверки

`npm test` проверяет валидацию ввода, скорость диагонального движения, границы, столкновения и настоящий Colyseus-сервер с двумя WebSocket-клиентами: общую комнату, репликацию, поток сообщений, истечение ввода и отключение. Интеграционный тест использует локальный порт 26789.

`npm run test:browser` запускает Chromium через Playwright, проверяет сцену Babylon (10 зданий и второй персонаж), захват мыши, движение WASD, отображение перемещения у второго игрока и удаление его модели после отключения. По умолчанию нужен `/usr/bin/chromium`; другой исполняемый файл задаётся через `CHROMIUM_PATH`. Dev-сервер запускается тестом автоматически.

## Границы прототипа

Одна улица без сохранения мира, аккаунтов, чата, экономики, магазинов и симуляции сетей. Нет предсказания движения или распределения нагрузки между процессами. Это основа для разработки, не готовая массовая MMO. Комнаты и игроки исчезают при перезапуске сервера.

## NETCITY-002: заявка №001

При подключении автоматически выдаётся заявка «В офисе пропала сеть». Пройдите к центру улицы (z≈0): **справа офис №001**, вход в открытой двери. Пройдите прямо по коридору через вторую дверь в серверную. У задней стены находятся стойка, коммутатор на восемь портов, патч-панель и кабели.

Подойдите к коммутатору на расстояние **не более 2,5 метра**, наведите прицел и нажмите **E**. В панели порт №3 отмечен как отключённый. Выбор другого порта выдаёт ошибку; подключение порта №3 восстанавливает сеть. Сервер подтверждает выполнение заявки и выдаёт одну отметку-награду (это счётчик выполнения, не экономика). Повторные запросы награду не увеличивают.

Оборудование общее для комнаты: второй игрок видит зелёный порт №3 и исчезновение отключённого патч-корда сразу после ремонта. У каждого игрока своя заявка. Если сеть уже исправлена другим игроком, осмотрите оборудование и подтвердите порт №3 для завершения своей заявки. Состояние заявки и награды хранятся только в текущей игровой сессии; после нового подключения выдаётся новая заявка. Аккаунтов и постоянного хранилища нет.

На смартфоне используйте **джойстик слева** и **свайпы по правой половине экрана** для обзора; у коммутатора нажмите **«Осмотреть»**. Панель оборудования и карточка заявки адаптируются к размеру экрана, описание заявки можно свернуть. Управление поддерживает одновременное движение и обзор; открытие панели останавливает движение. Для смартфона подключайтесь по локальному адресу компьютера с Vite, порт 5173, либо используйте HTTPS при размещении.

Сервер проверяет столкновения с наружными стенами офиса, перегородкой серверной и стойкой. Дверные проёмы открыты. Все координаты, этап заявки, результат ремонта и награду изменяет только сервер. Клиент передаёт `inspect` или `connect` с номером порта; перед каждой операцией сервер заново проверяет расстояние и предварительный осмотр.

Дополнительно проверяются: граница взаимодействия 2,5 м, поддельные координаты в действии, неправильные порты, осмотр перед ремонтом, повторная награда, проход через двери и столкновения со стенами. Интеграционный тест проверяет репликацию состояния оборудования двум настоящим клиентам. Браузерные сценарии проходят заявку через WASD/E и через настоящие touch-события (джойстик, свайпы, кнопка), проверяют панель в альбомной и портретной ориентации.


## Визуальная доработка и стабильность

Улица получила пешеходный переход, разметку, бордюры, плитку тротуаров, фонари, деревья в кашпо, скамейки и люки. У зданий есть цоколи, карнизы и оконные рамы. Офис узнаётся по козырьку, вывеске и цветному маршруту на полу; серверная — по указателю, потолочным световым полосам и маркировке оборудования. Все модели и текстовые таблички создаются кодом Babylon.js, внешних ассетов нет.

Другие игроки отображаются как процедурные модели людей. Сервер выдаёт имена «Инженер 01», «Инженер 02» и т.д. в пределах комнаты; клиент не может менять имя через сообщения движения. Ходьба анимируется на основе реплицируемого перемещения, поворот сглаживается через границу углов. Никнеймы видны рядом с персонажами, удалённые метки и модели скрываются для сокращения нагрузки.

HUD показывает текущий шаг и прогресс заявки. На телефоне описание и список этапов изначально свёрнуты; их можно раскрыть. Уведомления различают успешные и ошибочные действия цветом и текстом. Панель оборудования поддерживает Tab/Shift+Tab, закрытие Escape и возврат фокуса в игру. При открытии панели, потере фокуса и уходе вкладки в фон движение прекращается; остановка сразу отправляется серверу.

Исправлены серверные коллизии открытых дверных полотен и проверка взаимодействия из-за задней стены офиса. Центральный проход через обе двери остаётся доступным в обе стороны. При отключении клиента освобождаются движок, сцена, таймер и обработчики управления; повторное закрытие сессии безопасно. Переподключение создаёт новую сессию, поскольку восстановление старой сервером не поддерживается. Игровая заявка по-прежнему выдаётся заново, оборудование остаётся общим для существующей комнаты.

Оптимизация: статичные городские детали объединяются по общим материалам, неподвижные матрицы и материалы заморожены, кабели имеют малое число граней, поиск цели выполняется 10 раз в секунду. Тяжёлые динамические тени и постэффекты не используются. На сенсорных устройствах разрешение рендера составляет 80% CSS-размера без умножения на devicePixelRatio, сглаживание отключено. Используются выборочные импорты Babylon.js: основной JS-файл сборки сократился примерно с 6,32 до 1,32 МБ (до gzip, без отдельных шейдерных чанков). Vite всё ещё предупреждает о чанке больше 500 КБ.

`npm run test:browser` дополнен проверками человеческой модели, никнейма и анимации, разрыва WebSocket, трёх циклов переподключения и быстрых повторных попыток. Проверяется, что после разрыва не остаётся движка, после подключения есть ровно одна сцена и render loop, а число мешей, материалов и текстур возвращается к исходному. При уходе другого игрока освобождается его именная текстура. Это проверка жизненного цикла ресурсов, не длительный нагрузочный тест или гарантия частоты кадров на всех телефонах.
